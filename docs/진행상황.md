# 진행 상황

> Claude Code는 새 세션마다 이 파일을 먼저 읽고, **다음 Phase 하나만** 진행한 뒤
> 이 파일을 갱신하고 커밋한다.

  → `assets/models/sappun.glb` (`id`도 `choco` → `sappun`)

    그다음 `... resize 결과.glb 최종.glb --width 1024 --height 1024`
    (삼각형 195만 → 3.9만, 텍스처 2048 → 1024)
  - **뼈대(뼈·관절)가 없는 모델이라** 팔다리를 따로 못 움직인다. 대신 몸 전체를
    통통 튀기고 갸웃거리게 했다 → `character-model.js`의 `HOP` `FLOAT` `TILT`
  - 예전 코드 도형 버전은 `characters.js`에 주석으로 남겨뒀다. 비교해보고 싶으면 살리면 된다

  - 삼각형 5,900~18,200개. 사뿐핑만 38,994로 좀 많다 (먼저 만든 거라 설정이 달랐다)

- ✅ **추가** 놀이터에서 **그네·미끄럼틀·시소를 진짜로 탄다** → `src/rides.js`
  - 놀이기구 옆에 가면 오른쪽에 노란 **🎠 타기 버튼**이 나타난다 (키보드는 **E**)
  - **그네**: 의자에 올라타면 몸이 그네를 따라 기울고, 누가 타면 **더 크게** 흔들린다
    (`playground.js`의 `SWING_RIDE_AMP`). **내리기**를 누를 때까지 계속 탄다
  - **미끄럼틀**: 사다리 오르기 → 발판 건너기 → 슝(점점 빨라진다) → 폴짝, 전부 자동.
    다 내려오면 저절로 내린다 (`autoEnd:true`)
  - **시소**: 앞뒤로 **자리가 2개**다. 아이가 한쪽에 타면 마을 친구가 반대쪽에 와서
    **마주 보고** 탄다. 한쪽이 올라가면 반대쪽은 내려간다. 누가 타면 더 크게
    오르내린다 (`SEESAW_RIDE_AMP`)
  - **마을 친구(NPC)들도 스스로 놀러 온다.** 쉬고 나서 `RIDE_CHANCE`(0.4) 확률로
    빈 놀이기구를 골라 걸어가서 타고 논다 → `npcs.js`
    자리를 미리 맡아두기 때문에 한 그네에 두 명이 겹치지 않는다
  - 자리는 모두 **5개** (그네 2 + 미끄럼틀 1 + 시소 2)
  - 놀이기구 하나는 `{ kind, label, enter, exit, duration, autoEnd, rider, pose() }`
    모양이면 된다. **`playground.js`에 하나 더 밀어 넣으면 새 놀이기구도 바로 탈 수 있다**
    (`makeSwingRide` / `makeSlideRide` / `makeSeesawRide`를 흉내 내면 된다)
  - 캐릭터에 뼈대(관절)가 없어서 "앉는" 자세는 못 만든다. 의자 위에 **올라선 채**
    몸 전체가 기우는 방식이다
  - 이것 때문에 놀이기구 크기를 키웠다:
    미끄럼틀 지붕(가장 큰 친구 열이, 키 3.1이 발판에 서도 안 닿게)과
    그네 가로대(`BAR_Y` 3.4 → 4.6, 줄도 같이 길어짐). 시소는 위에 걸리는 게 없어서 그대로다

- ✅ **추가** 🏰 **성 안으로 들어간다** — 성 정문 앞에 서면 새로운 공간이 펼쳐진다
  → `src/castle-interior.js` (방·조명·문·타기), `src/castle-props.js` (가구)
  - **공간(area)** 이라는 개념이 생겼다. 공간 하나는 이런 모양이다:
    `{ scene, spawn, yaw, collide, isBlocked, update, rides, doors }`

    **새 공간(예: 사탕 가게, 지하 보물창고)을 만들려면 이 모양으로 하나 더 만들면 된다.**

    화면이 잠깐 하얘졌다가(`#fade`) 다른 공간으로 넘어간다 → `main.js`의 `goThroughDoor`
    한 번 문에서 멀어져야 다시 들어가진다(문 앞에서 무한 반복 방지)
  - 성 안은 **처음 들어갈 때 한 번만** 만든다 (처음 로딩을 느리게 하지 않으려고)
  - 성 안 물건: 왕좌·벽난로(불이 흔들린다)·케이크 탁자·책장·곰인형 독서 자리·

  - **왕좌에 앉기 👑 / 흔들목마 타기 🐴** — 놀이터와 똑같은 `rides.js`를 쓴다.
    성 안 친구 5명도 스스로 왕좌에 앉으러 온다
  - 바닥(체크무늬)·벽지(분홍 허리띠+하트)·스테인드글라스는 전부 **Canvas 그림**이다

- 캐릭터 선택 화면 카메라가 너무 멀어서 요정이 작게 보이던 것 (`main.js`의 `sCam`)

- **.glb 압축 절차** (아빠 PC ↔ Claude 세션 분담):
  1. 아빠 PC (cmd): `chcp 65001` 후
     `for %f in (*.glb) do npx --yes @gltf-transform/cli@4 optimize "%f" "out\%~nf.glb" --texture-compress false --compress quantize --simplify true --simplify-ratio 0.007 --simplify-error 0.01`
     → 삼각형 약 1만 개, 파일 3~7MB
  2. GitHub 업로드 (웹 업로드는 **파일당 25MB, 한 번에 올리는 총량도 제한**이 있어 2~3개씩 나눈다)
  3. Claude 세션: `resize ... --width 512 --height 512` → 0.3~0.7MB
     (아빠 PC에서는 텍스처 명령이 `colourspace: parameter space not set`으로 실패한다. sharp 버그)

  캐릭터당 **삼각형 1만~1.5만 · 텍스처 512px · 0.5MB 이하**를 지킬 것.
  느려지면 `NPC_COUNT`를 16쯤으로 낮추는 게 가장 효과가 크다.
- **모델이 안 보이면** 브라우저 콘솔에 "모델을 불러오지 못했어요"가 찍힌다.

- **성 안에서 할 수 있는 것**(앉기·타기·잠자기·공부하기)은 `src/castle-rides.js`에 모아뒀다.

  `castle-interior.js`의 `rides` 배열에 넣으면 된다.
  - `verb` / `offVerb` = 노란 버튼에 뜰 글씨 (없으면 '타기'/'내리기')
  - `enterY` = 그 놀이기구가 있는 층 높이 (2층이면 `FLOOR2`).
    이걸 적어야 1층에서 2층 미끄럼틀을 붙잡는 일이 없다
  - `parts` = 화면에 같이 넣을 것 (떠오르는 Z·숫자)

### 고침 — 건물에서 나오면 건물에 가려서 캐릭터가 안 보이던 문제
카메라는 캐릭터 **뒤쪽 14칸**에 선다. 그런데 건물에서 막 나왔을 때는
캐릭터가 광장 쪽을 보고 서므로, 그 "뒤쪽"이 **방금 나온 건물 안**이었다.
그래서 카메라가 건물 속에 파묻혀 캐릭터가 벽에 가렸다.

**1) 카메라가 건물·나무 속이면 캐릭터 쪽으로 당긴다** (`src/player.js`)
- `safeCamDist()` — 카메라 자리가 `isBlocked`면 6번에 나눠 당겨보고 안 부딪히는 자리를 쓴다
- 당긴 만큼 **눈높이와 바라보는 높이도 같이 내려온다.**
  ★ 이걸 안 하면 카메라만 가까워지고 시선은 그대로 위를 봐서
    **캐릭터가 화면 아래로 밀려 안 보인다** (처음에 이렇게 만들었다가 고쳤다)
- 값: `CAM_MIN`(4.5, 최소 거리) `CAM_PROBE`(1.2, 카메라 굵기)
  `CAM_NEAR_LOOK`(1.4, 바짝 당겼을 때 보는 높이)
- **마을에서만 켠다** (`world.js`의 `camCollide: true`).
  실내는 벽이 안쪽만 보이는 판이라 카메라가 밖에 있어도 잘 보이고,
  가구마다 카메라가 당겨지면 오히려 답답하다

**2) 문 앞에 서는 자리를 더 멀리** — 문에서 3.6칸 → **6칸**
  (카메라가 덜 당겨져도 되니 화면이 넓게 나온다)

**3) 문 앞 길에는 나무를 안 심는다** — 나무가 화면을 가리던 것
  (`reserved`에 문 앞 길을 추가. 마트·그림의 집은 반경 15/14 → **17**)

**4) 카메라가 다시 뒤로 빠질 때 덜컹거리던 것** (아이가 알려준 것)
- 당겨보는 자리를 `CAM_STEPS`칸으로 **뚝뚝 끊어서** 골랐는데,
  카메라 **위치**는 부드럽게 따라가지만 **시선(`lookAt`)은 그 끊긴 값을 즉시** 쓴다.
  그래서 시선이 계단처럼 튀어서 화면이 덜컹거렸다
- `camDist`를 따로 두고 **매 프레임 조금씩** 그쪽으로 다가가게 고쳤다 (`stepCamDist`)
  - `CAM_IN_RATE`(14) — 당길 때는 빠르게 (안 그러면 벽에 잠깐 파묻힌다)
  - `CAM_OUT_RATE`(2.2) — 물러날 때는 천천히 (약 1초에 걸쳐 원래 거리로)
  - `CAM_STEPS` 6 → **14** (더 촘촘하게)
- 재보니 한 프레임에 0.5칸 넘게 튄 횟수가 **12번 → 0번**
- ★ `main.js`는 `dt`를 0.05로 묶어둔다(279줄). 그래서 프레임이 낮은 기기에서는
  천천히 돌아오는 것처럼 보인다. 60fps에서는 약 1초다
- `player.camDist`로 지금 카메라 거리를 볼 수 있다 (덜컹거림 확인용)

### 고침 — 회전목마에서 말과 캐릭터가 따로 돌던 것 (아이가 알려준 것)
**Three.js 회전 방향을 반대로 알고 있었다.**
그룹을 `rotation.y = +θ`로 돌리면 그 안의 점은 **각도가 줄어드는** 쪽으로 간다.
그런데 타는 사람 자리는 각도가 **늘어나는** 쪽으로 계산해서, 둘이 **반대로 돌았다.**
(재보니 최대 **169도**까지 어긋났다 — 캐릭터가 자리 반대편까지 간다)

- 확인법: **캐릭터 각도 + 회전목마 회전각**이 늘 같은 값이어야 한다.
  이 값이 변하면 따로 도는 것이다
- 같이 고친 것:
  - 타는 사람이 자리보다 **1칸 바깥**에 앉는다 (`CAROUSEL_OUT`).
    카메라가 바깥에서 보기 때문에, 달·별 장식이 캐릭터를 가리지 않게
  - 매다는 봉도 안쪽으로 옮겼다
  - **`ride.camYawAt(t)`** — 놀이기구가 카메라 각도를 직접 정할 수 있게 했다
    (`player.js`). 회전목마는 카메라를 늘 바깥쪽에 둬서 기둥에 안 가린다
  - 탈 때 카메라가 캐릭터 높이를 보게 (`lookHeight: 3.0`)

## 고침 — 회전목마 '타기' 버튼이 아예 안 뜨던 것 (아이가 또 알려준 것)

### 무슨 일이었나
지난번에 타는 자리를 12곳으로 늘렸는데도 여전히 버튼이 안 떴다.
이번 원인은 **자리 문제가 아니라 마을 친구(NPC) 문제**였다.

- 루하성에는 친구가 4명 돌아다닌다(`npcCount: 4`)
- 회전목마와 달 그네에 `duration: 999`(999초 동안 탄다)라고 적혀 있었다
- 친구는 **`duration`이 다 지나야 내린다** (`npcs.js`)
  → 즉 친구가 한 번 올라타면 **999초, 사실상 영영 안 내린다**
- 놀이기구는 누가 타고 있으면(`ride.rider`) 빈자리로 안 쳐준다
  → 아이한테는 '타기' 버튼이 영영 안 뜬다

게임을 켜고 **10초쯤 지나면** 친구가 올라타서 그때부터 버튼이 사라졌다.
그래서 "될 때도 있고 안 될 때도 있다"처럼 보였던 것이다.

### 어떻게 고쳤나 → `src/ruha-castle.js`
```js
// 회전목마 · 달 그네 둘 다
noNpc: true,      // ★ 친구는 안 탄다. 여긴 아이 자리다
duration: 60,     // ★ 넉넉하되 무한이 아니게 (autoEnd:false라 아이는 계속 탄다)
```
- `noNpc: true` → 친구가 아예 안 올라탄다. **회전목마는 아이 자리.**
- `duration: 60` → 혹시 누가 타더라도 1분이면 반드시 내린다 (막히지 않는다)
- 덤: **달의 옥좌** 감지 거리를 5.0 → 4.0으로 줄였다.
  옥좌가 너무 넓게 잡아서 회전목마 앞에 서도 '앉기'가 떠 버렸다

### 규칙으로 기억할 것
> **놀이기구에 `duration`을 아주 크게 적지 마라.**
> 친구가 타면 안 내려서 아이가 못 탄다.
> 아이 전용으로 두고 싶으면 `noNpc: true`를 꼭 붙인다.

### 같은 실수를 미리 막은 곳 → `src/castle-rides.js`
인하성 **침대·책상**도 `duration: 600`(10분)이었다. 아직 문제가 안 났을 뿐,
친구가 앉으면 10분 동안 아이가 못 쓴다 → **60초**로 줄였다.
(아이는 `autoEnd: false`라 '일어나기'를 누를 때까지 그대로 있는다. 아이한테는 달라지는 게 없다)

### 확인한 방법
- 60초 동안 지켜보며 매 순간 버튼과 놀이기구 주인을 찍어봤다
  → 고치기 전: 10초부터 계속 `회전목마: 친구가탐`, 버튼 없음
  → 고친 뒤: 60초 내내 `빈자리`, 버튼 `타기`
- 회전목마 둘레 12곳에서 전부 '타기'가 뜨는지, 타고·돌고·내리는지도 확인
- 마트/친구 집/그림의 집/인하성/징검다리 걷기까지 다시 돌려봤다 (콘솔 깨끗)
