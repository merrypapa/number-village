# 멀티 에이전트로 게임을 계속 업그레이드하기

> 아빠용 설명서. "에이전트 여러 개가 알아서 게임을 키우게 하는 법".

---

## 1. 왜 에이전트를 나누나

한 명한테 "게임 더 재밌게 만들어줘"라고 하면 매번 다른 걸 건드리고,
파일이 400줄을 넘고, 어제 되던 게 오늘 안 된다.

그래서 **역할을 나누고, 각자 고칠 파일을 정해준다.**
파일이 겹치지 않으면 여러 명이 동시에 일해도 충돌이 없다. 이게 핵심이다.

| 에이전트 | 하는 일 | 고칠 수 있는 파일 |
|---|---|---|
| `planner` | 다음에 만들 것 **하나** 고르기 | 문서만 |
| `character-artist` | 캐릭터 생김새·애니메이션 | `src/characters.js`, `src/character-*.js` |
| `world-builder` | 마을·건물·하늘·부딪힘 | `src/world.js`, `src/playground.js`, `src/sky.js` |
| `gameplay-ui` | 조작·NPC·도감·저장·화면 | `src/main.js`, `player.js`, `npcs.js`, `ui.js`, `save.js`, `index.html` |
| `rule-reviewer` | 규칙 위반 검사 (**고치지 않음**) | 없음 |
| `qa-runner` | 실제로 띄워서 콘솔 에러 확인 (**고치지 않음**) | 없음 |

정의는 `.claude/agents/*.md` 에 있다. 그냥 마크다운 파일이라 아빠가 직접 고쳐도 된다.
맨 위 `---` 사이가 설정이고, 그 아래가 그 에이전트한테 주는 지시문이다.

---

## 2. 한 사이클은 이렇게 돈다

```
      docs/작업큐.md
            │
     ① planner ── 작업 1개 + 담당 + 고칠 파일
            │
     ② 담당 에이전트 1명이 구현
            │
     ③ rule-reviewer  +  qa-runner   (동시에, 둘 다 안 고침)
            │
        합격? ──아니오→ 사유 들고 ②로 (최대 2번)
            │예
     ④ 진행상황 갱신 → 커밋 → push
```

**한 사이클 = 작업 하나 = 커밋 하나.** 이 규칙을 깨면 금방 엉킨다.

만드는 사람과 검사하는 사람을 나눈 게 두 번째 핵심이다.
자기가 짠 코드를 자기가 검사하면 항상 합격이 나온다.

---

## 3. 실행하는 법

### 손으로 한 사이클
클로드 코드에서:

```
/업그레이드
```

아이가 원하는 게 있으면 뒤에 붙인다:

```
/업그레이드 무지개 미끄럼틀 만들어줘
```

그럼 그게 1순위가 된다.

### 알아서 계속 돌게 (한 세션 안에서)
```
/loop 30m /업그레이드
```
30분마다 한 사이클씩 돈다. 아빠는 옆에서 보다가 이상하면 끼어들면 된다.

### 밤에 알아서 돌게 (세션 없이)
클로드 코드 웹/앱에서 이렇게 말하면 예약이 걸린다:

> 매일 밤 11시에 `/업그레이드` 를 한 번 실행하는 루틴 만들어줘

아침에 브랜치를 열어서 아이랑 같이 보면 된다.

### 깃허브에서 돌게 (선택)
이슈에 `@claude` 를 달면 그 이슈를 작업 큐처럼 쓸 수 있다.
`.github/workflows/` 에 아래 파일을 만들고, 저장소 Secrets에 `ANTHROPIC_API_KEY` 를 넣는다.

```yaml
name: 게임 업그레이드
on:
  schedule:
    - cron: '0 14 * * *'      # 매일 밤 11시 (한국시간)
  workflow_dispatch:
jobs:
  upgrade:
    runs-on: ubuntu-latest
    permissions: { contents: write, pull-requests: write }
    steps:
      - uses: actions/checkout@v4
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          prompt: "/업그레이드"
```

> 자동 머지는 걸지 마세요. 게임에 뭐가 들어갈지는 아이랑 아빠가 정하는 게 이 프로젝트의 목적입니다.

## 4. 동시에 여러 개 돌리고 싶으면

파일 주인이 다르니까 **담당이 다른 작업 2~3개는 동시에** 돌려도 된다.

```
캐릭터 작업 (character-artist)  ─┐
마을 작업   (world-builder)     ─┼→ 각자 다른 파일 → 충돌 없음
```

단, `gameplay-ui` 는 `main.js` 를 갖고 있어서 거의 모든 작업과 겹친다.
**gameplay-ui 작업은 항상 한 번에 하나만** 돌린다.

그리고 `docs/진행상황.md` 는 모두가 마지막에 고치는 파일이라 자주 부딪힌다.
동시에 돌릴 때는 각 사이클을 다른 브랜치(워크트리)에서 돌리고 나중에 합치는 게 안전하다.

---

## 5. 이게 잘 도는지 보는 법

한 사이클이 끝났을 때 이 네 개가 다 참이어야 한다.

1. `python3 -m http.server 8000` 으로 띄우면 **콘솔 에러 0개**
2. 화면에서 **눈에 보이는 변화**가 하나 있다 (아이한테 보여줄 게 있다)
3. `docs/진행상황.md` 가 갱신됐다
4. 커밋이 **한 줄 한국어**다

하나라도 아니면 그 사이클은 실패다. 되돌리고 다시 한다.

`node scripts/smoke-test.mjs` 로 1번을 자동으로 확인할 수 있다.
(Playwright가 깔린 컴퓨터에서만 돈다. 없으면 그냥 건너뛴다 — 게임에는 영향 없음)

## 6. 파일 지도

```
.claude/
├── agents/          에이전트 6명의 지시문 ← 여기를 고치면 성격이 바뀐다
│   ├── planner.md
│   ├── character-artist.md
│   ├── world-builder.md
│   ├── gameplay-ui.md
│   ├── rule-reviewer.md
│   └── qa-runner.md
└── commands/
    └── 업그레이드.md   /업그레이드 슬래시 커맨드 = 사이클 순서
docs/
├── 기획안.md         무엇을 만드는 게임인가 (안 바뀜)
├── 진행상황.md       지금까지 만든 것 (사이클마다 갱신)
├── 작업큐.md         앞으로 만들 것 ← 아이 요청을 여기 적는다
└── 멀티에이전트.md    이 문서
scripts/
└── smoke-test.mjs   콘솔 에러 0개 자동 확인
```

## 7. 자주 나는 문제

**에이전트가 자기 담당 아닌 파일을 고쳤다**
→ `planner` 가 작업을 너무 크게 잘랐다는 뜻이다. 작업을 더 작게 나눠야 한다.

**매번 반려가 난다**
→ `rule-reviewer.md` 의 반려 조건이 실제 코드와 안 맞을 수 있다. 조건을 고친다.

**게임이 점점 무거워진다**
→ 작업큐에 "성능 정리" 작업을 넣고 한 사이클을 통째로 쓴다. 새 기능은 그 사이클에 넣지 않는다.

**아이가 원한 게 안 나온다**
→ `docs/작업큐.md` 맨 위 "아이가 요청한 것"에 적혔는지 본다. planner는 거기부터 본다.
