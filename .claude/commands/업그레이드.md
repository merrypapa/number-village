게임 업그레이드 1사이클을 돈다. **한 사이클에 작업 하나만** 한다.

추가 요청: $ARGUMENTS

## 순서

### 1) 기획
`planner` 에이전트를 부른다.
- `$ARGUMENTS` 가 있으면 그것을 "아이가 요청한 것"으로 취급해 최우선으로 넘긴다.
- 없으면 `docs/작업큐.md` 에서 알아서 고르게 한다.
→ 결과: 이번 작업 1개 + 담당 + 고칠 파일.

### 2) 구현
planner가 지정한 담당 에이전트(`character-artist` / `world-builder` / `gameplay-ui`)
**하나만** 부른다. 지정된 파일 외에는 건드리지 못하게 프롬프트에 파일 목록을 그대로 넣는다.

여러 담당이 필요한 작업이면 그건 작업이 너무 큰 것이다.
planner에게 되돌려 더 작게 자르게 한다.

### 3) 검수 + 실행검사 (동시에)
`rule-reviewer` 와 `qa-runner` 를 **한 번에 같이** 띄운다. 둘 다 코드를 고치지 않는다.

### 4) 반려면 고치기
둘 중 하나라도 반려면, 사유를 그대로 담당 에이전트에게 돌려보내 고치고 3)을 다시 한다.
**최대 2번까지만** 반복한다. 세 번째도 반려면 `git restore` 로 되돌리고,
`docs/작업큐.md` 의 그 작업 밑에 "막힌 이유"를 적고 끝낸다. 반쯤 만든 상태로 커밋하지 않는다.

### 5) 마무리
- `docs/진행상황.md` 갱신 (완료 표시 + 알려진 이슈)
- `docs/작업큐.md` 에서 끝난 작업 지우기
- 한국어 한 줄로 커밋: 예) `감정 요정 4명 추가`
- `git push -u origin` 현재 브랜치

## 절대 지킬 것
- 사이클마다 게임은 **반드시 실행 가능**해야 한다. 콘솔 에러 0개.
- 담당끼리 파일을 넘나들지 않는다. 그래야 여러 사이클을 동시에 돌려도 충돌이 없다.
- 자동으로 main에 머지하지 않는다. 아이랑 아빠가 직접 보고 정한다.
